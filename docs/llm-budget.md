# LLM: варианты и бюджет

Проверено 23.10.2026. Это расчёт по открытым тарифам, а не результат измерения нашего приложения. Платных вызовов не было. Бюджет и провайдер пользователем ещё не утверждены. Приоритет — минимальные расходы; защита ожидается в июне–июле 2027 года.

## Рекомендация

Сначала оформить контракт извлечения критериев и тестовый набор. Затем сравнить максимум две недорогие модели на одинаковых запросах: кандидат через OpenRouter/прямой DeepSeek и кандидат с рублёвой оплатой через Yandex AI Studio. Не покупать подписку и не арендовать GPU. Бесплатный режим полезен для знакомства, но на защите нужен автономный сценарий на правилах с явной маркировкой.

OpenRouter — шлюз, а не модель. Тариф прямого DeepSeek нельзя автоматически считать тарифом той же модели в OpenRouter. Перед подключением сохранить ID модели, выбранный endpoint, поддержку структурированного ответа и фактическую цену. До этого рекомендация относится к способу сравнения, а не к окончательному победителю.

| Правила + текущая SQLite | 0 ₽ за LLM | Воспроизводимая исходная версия и автономная демонстрация. Не решает понимание произвольного текста |
| OpenRouter Free | Страница тарифа указывает 50 запросов/день | Первые опыты; доступность модели и квоты проверять в аккаунте. Не основа для массового теста или обещания стабильности |

| Yandex AI Studio, Qwen3.6 35B | 0,20 ₽ / 1000 входа; 0,30 ₽ / 1000 выхода, с НДС | Второй кандидат рублёвого API, если первый не справится |

| Локальная модель через Ollama | Нет платы за внешний inference при локальном запуске | Есть расход памяти, электричества и времени. Проверить компьютер и лицензию модели; не покупать железо ради экономии нескольких долларов |

Это список кандидатов по цене и способу доступа, а не рейтинг качества русского языка. Доступность оплаты и конкретного endpoint для аккаунта ещё не проверена. Более новая или крупная модель не обязательно лучше извлекает наши фильтры.

## Сколько стоит именно наш сценарий

Допущение: один разбор запроса = **1500 входных + 400 выходных токенов**. Во вход входят инструкция, схема и текст пользователя. Это рабочее допущение; русскую токенизацию измерить по `usage`, а не по числу слов. Нет истории всего диалога, описаний 26 тысяч квартир, web search и генерации текста для каждой карточки. Кеш и скидки не заложены.

Формула: число вызовов × (входные токены × тариф входа + выходные токены × тариф выхода). Единицы тарифов привести к одному токену.

| Прямой API | 100 вызовов | 1000 вызовов | 5000 вызовов |
|---|---:|---:|---:|
| DeepSeek Flash, peak | $0,093 | $0,93 | $4,65 |
| Gemini 2.5 Flash-Lite, paid | $0,031 | $0,31 | $1,55 |
| Alice AI LLM Flash | 23 ₽ | 230 ₽ | 1150 ₽ |
| Qwen3.6 35B через Yandex | 42 ₽ | 420 ₽ | 2100 ₽ |
| YandexGPT Pro 5.1 | 152 ₽ | 1520 ₽ | 7600 ₽ |

Это расход токенов, не минимальная сумма пополнения. Цены прямых API не перенесены на OpenRouter. Доллары не пересчитаны по выдуманному курсу; фактический платёж зависит от способа оплаты.

Если вход и выход окажутся вдвое длиннее, стоимость удвоится. Повторы/уточнения — дополнительные вызовы. Например, 5000 поисков с запасом 30% дают 6500 вызовов: $6,045 у прямого DeepSeek Flash либо 1495 ₽ у Alice Flash при тех же размерах. Платные reasoning-токены, если включены, также увеличат расход.

### Этапы расхода

1. До подключения: 0 ₽, моки, схема, правила, ручная разметка.
2. Первый пилот: до 600 вызовов суммарно на две модели, включая настройку и проверку. Если все выполнить на Alice Flash, расчёт — 138 ₽; на прямом DeepSeek Flash — $0,558. Реальный смешанный расход считать по провайдерам отдельно.
3. ВКР целиком: ориентир 3000–5000 вызовов суммарно, включая пилот, повторные эксперименты, демонстрации и пользовательские тесты. Это план нагрузки, не измеренное потребление. Для экономичного кандидата ориентир $2,79–4,65 прямого DeepSeek либо 690–1150 ₽ Alice Flash, до запасов и пополнений.
4. Дополнительные дорогие контрольные модели ограничить отдельным малым прогоном, например 100 запросами; согласовать до запуска.

### Семантический поиск

Для 26 528 объектов при 500–1500 токенах на описание получается 13,264–39,792 млн токенов. Тариф эмбеддингов Yandex 0,0101 ₽ / 1000 даёт **примерно 134–402 ₽ за один полный проход**. Средняя длина ещё не измерена; это диапазон сценариев, а не статистика нашей базы. Векторизацию повторять только для изменённых объектов, хранить версию модели и хеш текста. Проверить лимиты длины и размерность до полного прохода.

Альтернатива — локальная модель эмбеддингов без внешних токенных платежей; потребуются ресурсы компьютера и проверка качества русского поиска. До выбора провести маленький замер на нескольких сотнях объектов. Дообучение LLM не требуется. CatBoost — необязательный этап при наличии разметки, а не условие работающего MVP.

### Сервер и остальные расходы

- Локальная разработка, SQLite и демонстрация на своём компьютере: 0 ₽ за аренду и домен. Расход электричества/интернета не оценён.
- Внешняя площадка до собеседований не обязательна: репозиторий с инструкцией и короткая запись работы позволяют показать кейс.
- Для внешней демонстрации можно заложить **резерв 500–1000 ₽ на один месяц** небольшой VM. Это бюджетный резерв, не проверенный тариф конкретного хостинга и не гарантия достаточных ресурсов. Выбирать тариф после измерения памяти; локальную LLM на такую VM не закладывать.
- Домен, GPU, отдельный платный векторный сервис, Redis и платный мониторинг на старте не нужны.
- Бесплатный Metrapi учитывать только в пределах подтверждённого срока. В письме указано «по июнь включительно», год и доступ до июльской защиты нужно уточнить. Сохранённый снимок позволяет защитить автономный сценарий; свежесть честно обозначать.

## Предлагаемые ограничения расходов

Предложение, **не разрешение на списание**: пилот не более 200 ₽ эквивалента; после замеров общий резерв на LLM+эмбеддинги 1500 ₽ эквивалента. Для внешнего сервера отдельно максимум один месяц, если он нужен. Долларовое пополнение может быть больше фактического расхода, поэтому сначала проверить checkout. При достижении лимита остановить вызовы, а не докупать автоматически.

Технически предусмотреть:

- ключ только на сервере, фиксированный список моделей, платные вызовы выключены по умолчанию;
- лимит входа/выхода, тайм-аут, максимум один управляемый повтор; не повторять ошибку оплаты;
- ограничение одновременных вызовов и частоты, особенно до публичной демонстрации;
- учёт `usage`, модели/провайдера, версии промпта, времени и цены; не логировать ключи;
- хранение проверенного профиля поиска, чтобы смена страницы и сортировки не вызывала модель повторно;
- ограниченный кеш разбора с учётом версии схемы/модели, без смешивания приватных сессий;
- лимит ключа у провайдера и локальный учёт с резервом под незавершённые вызовы;
- явное сообщение при недоступности LLM; режим правил не выдавать за результат модели.
